# 《王座与黄金》四维试玩报告

日期：2026-11-20 · 版本：`2cd83c2`（v1.0.0，`release/index.html` 303,061 字节）
方法：四个只读试玩子进程（世界观 / 成长 / 可玩 / 易玩）各自跑 25–100 年模拟、读源码与构建产物；主线程对关键结论做独立复核。**未改任何被跟踪文件**。

---

## 0. 结论

**综合 3.3 / 10。世界模拟 7 / 10，玩家体验 1.5 / 10。**

| 维度 | 评分 | 一句话判词 |
| --- | --- | --- |
| 世界观与叙事 | **4** | 骨架是世界级的，血肉没长上去：4.5 万字历史里 87.2% 没有一个专名 |
| 成长性 | **3** | 40 年净资产 3,026 → 54,778，其中 74% 是"别人死了送的"和"2% 抽成"，玩家按不按按钮只差 1.21× |
| 可玩性 | **2** | 25 年只出现 4 次抉择、14 次主动操作；30× 下每秒 4.8 个弹窗 |
| 易玩性 | **4** | 能看懂界面，但看不懂游戏：没有目标、没有收入、"自动存档"不自动 |

四份报告独立跑出的数字互相咬合——这不是四个毛病，是同一个结构问题的四个切面：**世界会自己转，但玩家不在传动链上。**

## 1. 四个根因（四份报告交叉验证）

### R1 经济账本不闭合：赚钱的是账面，不是玩家

- **假利润**：`src/systems/organization/Finance.ts:80-81` 把 `tradeRevenue` 全额计入 `grossProfit`，但 `:93` 的现金行既不加 `tradeRevenue` 也不减采购成本（采购在 `TradeSystem.ts:166` 扣现、不进损益）。实测 40 年账面利润 **906,979**，股东权益只增 **19,267**（2.1%）。UI 的"上月利润"、组织估值、净资产全部虚高约 5 倍。
- **无分红**：`Finance.ts` 全文没有股东分配。玩家 71% 股份 40 年现金流 0；唯一回流是领袖 2% 抽成（`CharacterSystem.ts:43-46`），40 年 19,765 铜 = 账面利润的 2.18%。
- **国家被写小一个量级**：`CountrySystem.ts:29` `HEAD_TAX_PER_CAPITA = 0.02`、`:47` 按 `人口 × 0.02 × 税率`、`:50` 国库只有这一项。7 国 29.2 万人口月入合计 **903**，而 `countries.json` 初始 `monthlyRevenue` 写 11,650 → 第 1 年国库 104,500 → 22,344，20 年后 **4,516**，同期组织现金 **1,725,271**（国/组 ≈ 0.003）。
- **公职薪水从不发放**：`Offices.ts:33-35` 的 `salaryMonthly` 140/130/110 是死字段。
- **"投资"不花玩家的钱**：`CommandBus.ts:161-180` 是 `org.cash -= amount; org.assets += amount`，玩家点击"投资"后自己现金不变，UI 文案却读作"我掏钱"。

### R2 玩家没有动词：25 年后能做的事和第 5 年一模一样

- 可直做动作只有：投资（字号现金）、买卖股份、接管字号、谋求公职、转行、战争四项（需统治权/影响力 ≥0.4）。**没有移动**（`Character.location` 无写入入口）、**没有技能训练**、**没有货品买卖**、**没有个人资金出口**（只能买股）。
- 技能 40 年 `trade 6 → 8`，唯一来源 `ev_adv_mentor`；商会主要 9、公职评分要 skill ≥ 9.09 → 职业与公职双死锁。
- 影响力只来自已持有官职（`Offices.ts:49-61`）→ 没官职就没影响力 → 商人开局评分 0.17，25 年只到 0.28，门槛 0.45，约需 4 万铜/80 年。
- 买股没有对手：`CommandBus.ts:628-664` 按最大股东强行买入，无溢价、无拒绝；最优开局只有一条——1500 铜在第 0 天吃掉 39% 当上掌柜。

### R3 事件是"广播"，不是"发生在你身上"

- **主体埋在灰字**：`EventDialog.ts:90-92` 标题只有事件名，主体在 `.modal__meta`（0.72rem、`--text-muted`、对比度 3.14:1）；`App.ts` 构造信号时把 `record.refs` 整个丢掉，UI 无法判断"与谁有关"。
- **无差别刷屏**：`App.ts:647-682` 把所有 `kind='event'` 记录无条件压成模态，`EventDialog.pushMany` 无上限无合并；25 年 **1,431 个弹窗**，30× 下每秒 4.8 个；月末一次 1,106/1,255 条集中爆发。
- **死人不退场**：`EventEngine.ts:350-361` 的 character 分支不筛 `alive`，人物事件又是季度抽样 → 100 年 2,621 条人物事件里 **1,425 条（54.4%）打在死人身上**；玩家第 59 年死后世界继续跑，十年后财富又从 0 涨到 680。
- **抉择不成立**：`src/main.ts:34` 是 `new GameEngine(state, content)`，没传 `{ stopAtChoices: true }` → 新开局玩家**永远看不到抉择**，全部被 `pickChoice` 自动代选；只有手动读档的 `adopt()` 才开。实测唯一抉择 `ev_adv_opportunity` 两选项 25 年差 5.8%，`hint` 为空。

### R4 没有牵引、没有结局

- 无目标/任务/结局字段；Tour 只讲控件；默认暂停，玩家不按空格就永远停在第 1 天。
- 玩家死亡只写一行 `c_player 去世`，`playerId` 仍指向尸体；金穗行领袖仍是死者，40 年后 `validateWorld` 仍返回 `[]`。
- "自动存档"只读不写：`main.ts:20` 只 `readSlot(AUTO_SLOT)`，全仓唯一 `writeSlot` 在 `SaveDialog.ts:186` 由点击触发 → 刷新必丢未手存进度。

### P1（有系统，玩家感觉不到）

1. **分红与俸禄**：年末 `max(0, 年度净利润) × 35%` 按股比入账（`Finance.ts`），公职按月发 `salaryMonthly`；PlayerPanel 显示"本月收入"。
2. **技能成长**：加 `train` 行动（6 个月 +1 主技能，上限 12，100 铜），`officeScore` 财富项系数 `/20`→`/12`，商会主 `minSkill` 9→8。
3. **移动与个人资金**：`move { regionId }`（按 `links[].days` 消耗天数）、`deposit`/`withdraw`（玩家↔组织现金）。
4. **收购有对手**：买股加 1.2–1.8× 溢价与拒卖概率，敌意收购推高 `conflict`。
5. **历史结构化**：`HistoryRecord` 加 `subject{kind,id,name,title}`、`place`、`cause`、`result`；统一 `Chronicler.render()`；测试禁止裸 ID。
6. **事件门控与占位符**：`EventDef.when:{countryIds,cultures,terrains,faiths}`；正文用真实人名/地名渲染（"石渡关雪崩"只在高谷）。
7. **政体扩展**：theocracy / tribal_confederation / merchant_league / military_order，各自官职表与继承规则。
8. **UI 泄漏清理**：`skill.trade`、`trait.ambition`、`merchant · r_greenfield`、`guild`、`faith_tide` 全部走 label 表。
9. **长面板滚动复位**、**不可逆动作二次确认**、**公职按钮显示"资历 18/45"并禁用**。
10. **战争与经济挂钩**：战时交战国 `importCapacity ×0.3`、粮价 +30%，顶栏"战时"标签。

### P2（打磨）

历法纪元名、国家人口与区域人口对齐（银月 83,000 vs 区域 68,000）、组织行业与地形匹配、名字里的官衔拆分、组织 `foundedDay` 错开、README 数字与实际一致（历史 10,278 vs 实测 15,939）、颜色对比度与最小字号（50+ 处 0.6–0.69rem）。

## 4. 建议实施顺序（三轮，每轮可独立交付）

### 第一轮：可玩性抢救（约 2 天）
P0-1 默认真抉择 → P0-2 弹窗过滤 + 按月聚合 + 自动暂停 → P0-3 死人退场 + 玩家死亡结算 → P0-6 自动存档。
**验收**：新开局 25 年内抉择 ≥ 4 次；玩家相关弹窗占比 < 10% 且单月 ≤ 3 条；`sim` 哈希变化但 `--check` 一致；135 例测试 + 3 个新回归用例。

### 第二轮：经济闭合（约 2 天）
P0-4 损益 → P0-5 国家税基 → P1-1 分红/俸禄 → P1-2 技能训练 → P1-3 移动与存取。
**验收**：40 年"主动 vs 躺平"差距 ≥ 2×；`年度 Δ权益/年度利润 ∈ [0.85, 1.05]`；国库/组织现金比回到 0.05–0.2；玩家 40 年内至少解锁 3 个新动词。

### 第三轮：叙事与新手（约 3 天）
P0-7 建议事项与目标 → P1-5 历史结构化 + Chronicler → P1-6 事件门控与占位符 → P1-8 文案/泄漏清理 → P1-7 政体扩展。
**验收**：历史含专名比例 > 80%；每国 ≥ 6 条本地事件；"本月见闻"卡片可展开；新手 10 分钟走查能说出"我下一步做什么"。

## 5. 已确认可直接开修的"真 bug"

以下 6 条已由主线程逐条核对源码，不依赖试玩推断：

1. `src/main.ts:34` 未传 `{ stopAtChoices: true }` → 新开局无抉择。
2. `src/systems/organization/Finance.ts:80-81` 与 `:93` 的 `tradeRevenue` 只进利润不进现金，采购成本只进现金不进利润。
3. `src/systems/country/CountrySystem.ts:29` `HEAD_TAX_PER_CAPITA = 0.02`，与 `countries.json` 的 `monthlyRevenue` 差 12.9×。
4. `AUTO_SLOT` 全仓只被 `main.ts:20` 读取，从未自动写入。
5. `src/core/EventEngine.ts:350-361` 的 `entitiesOfScope` 不筛 `alive`。
6. 玩家死亡后 `state.playerId` 不转移、`CharacterSystem.ts:117-121` 无继承人时领袖位保留死者 id。

## 6. 需要拍板

1. **先做哪一轮？** 建议第一轮（可玩性抢救），因为它不改经济数值、不动验收基线，且立刻可感知。
2. **数值改动是否接受验收基线漂移？** 第二轮会改变三 seed 的哈希与破产率/分裂率，需要重跑 `docs/acceptance.md` 的三 seed 表。
3. **是否继续用并行子代理？** 第一轮三人可并行（抉择/弹窗、死亡与结算、自动存档），第二轮建议串行（都改 `Finance`/`CountrySystem`，容易冲突）。
