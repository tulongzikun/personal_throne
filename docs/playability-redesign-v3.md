## 0. 要解决的是什么

诊断里最刺眼的三组数字：5 年 180 次点击只有 7 次真抉择；30 年官职 0；挂机 30 年与主动玩获得**一模一样的股份**。

这三件事指向同一个结构：**世界在演，玩家在旁观，唯一的接口是"建议事项"**。建议事项是一个求解器——它把状态算成三个最优动作，玩家照着点。于是：

- 玩家不需要理解世界，只需要信任面板；
- 玩家的动作不改变世界的走向，只改变自己的余额；
- 没有失败的可能，所以没有成功的意义。

**v3 的目标不是加内容，是把玩家从"世界的读者"变成"世界的当事人"。**

### 核心幻想

> 你从别人的棋盘上开始——欠着钱、靠着一两个熟人、手里只有三十天。
> 十年后你坐上桌，成为发牌的人；三十年后你离席，桌上还留着你的规矩。

这句话决定了系统的取舍：一切机制都要能回答"它如何让玩家更像一个**在有限时间里做交易的人**"。
不能回答的机制（更细的物价波动、更多的 NPC 背景故事）即使更"真"，也不进 v3。

### 三个必须出现的"啊哈"时刻

| # | 时刻 | 触发条件 | 为什么重要 |
| --- | --- | --- | --- |
| 1 | "原来他记得" | 玩家早期帮过/害过的 NPC，在第 8 年带着后果回来 | 世界有记忆，玩家不是过客 |
| 2 | "原来打听是有用的" | 花 3 天 20 铜确证一条风声，从而截住对手或避开陷阱 | 信息是武器，不是装饰 |
| 3 | "原来我死了世界还在" | 死亡结算 → 继承 → 债务与仇怨一并交给下一代 | 一生有终点，选择有重量 |

这三个时刻是 M1–M5 的验收核心：**没出现这三个时刻，系统做得再多也是失败。**

三条不可协商的体验目标：

1. **每月必须有一次"我必须在 X 之前做什么"的判断，且这个判断没有标准答案。**
2. **世界必须主动索取**：有人要你还钱、要你站队、要你交货、要你表态；不回应就是回应。
3. **一生必须有结算**：死亡是一次评分，不是一个暂停按钮。

五个反模式（明确不做）：

| 反模式 | 为什么不做 |
| --- | --- |
| 事件抽卡（随机给奖励） | 会把"压力"变成"赌博"，玩家只会刷 |
| 面板给最优解 | 这正是不好玩的根因 |
| 用数值膨胀当成长 | 48 → 54,778 已经证明没用 |
| 让玩家读 diff（`wealth: A → B`） | 玩家要的是因果叙事，不是账本 |
| 无限堆内容 | 靠系统生成处境，不靠手写卡片 |

## 1. 新核心循环

### 1.1 一句话

**每个月你拿到一份「处境」，不是一份「建议」；你用 30 天回答它，然后世界回答你。**

### 1.2 时间轴（一个月，真实分钟数）

| 秒 | 发生什么 | 玩家做什么 |
| --- | --- | --- |
| 0–20 | 处境板刷新：3 条紧急（带天数条）+ 2 条背景 + 1 条风声 | 读，判断哪条最要命 |
| 20–60 | 打开其中一条，看它要什么、给什么、过期会怎样 | 选一个应对（或先去打听） |
| 60–120 | 执行 2–4 个动作，日历随之推进（动作不是瞬间完成的） | 在"还债/赴宴/跑货"之间取舍 |
| 120–150 | 日历走完或被打断，月末结算 | 看月报：谁得到了什么、谁记恨了你 |

对比现在：0–10 秒读完一张见闻卡 → 点 3 下建议 → 按 30 天 → 什么都没有发生。

### 1.3 三层动机

```
本周期的处境（谁在催你） → 本年的野心（你想成为谁） → 一生的评价（你留下了什么）
```

三层之间必须**互相消耗同一种资源**（时间、钱、声望、人情），否则玩家会分开处理、互不干扰。

**主动与被动必须各占一半**：只有压力 = 被世界牵着走的苦工；只有计划 = 无人竞争的沙盒。
v3 的一半是「别人要你做的事」（S2 议程），另一半是「你自己想做的事」（S2b 计划）。

### 1.4 开局前 30 分钟（脚本，作为验收基准）

| 时间 | 玩家经历 | 教会他什么 |
| --- | --- | --- |
| 0–2 分 | 三选一背景：落魄商贾之女 / 退伍老兵 / 书吏之子。各带 1 个初始人情、1 笔初始债 | 你不是白纸，你背着东西进场 |
| 2–5 分 | 第一屏就是 3 条带天数的处境（不教控件） | 有人在乎你做什么 |
| 5–15 分 | 第一次被迫取舍：钱不够同时还债与赴宴 | 30 天不够用，必须放弃 |
| 15–25 分 | 第一次被对手抢走东西（可控挫败），用打听反制 | 世界有对手，情报能翻盘 |
| 25–30 分 | 第一次启动自己的计划（开一条小商路，3 阶段） | 你也能主动改变世界 |
| 第一个月末 | 月报：你被谁记住了、谁记恨了你 | 因果有回声 |

这 30 分钟不出现任何"建议事项"。如果玩家在这 30 分钟里问"我该点哪个"，设计就是失败的——他应该问"我先救哪一头"。

## 3. S1 时间预算：行动 = 天数

### 3.1 为什么先做这个

现在的时间是"看"的，不是"花"的：`advanceDays` 由 UI 调用，贩货瞬间完成还赚差价（`src/core/commands/personal.ts:200-259` 不推进日历），移动才推进（`src/ui/PlayerPanel.ts:278-279`）。于是月份没有取舍——3 点行动力点完，剩下 30 天与玩家无关。

### 3.2 规则

1. **每个玩家动作声明耗时**（天）。引擎在 `dispatch()` 内推进日历，UI 不再自己推进。
2. 行动力（AP）保留，但降级为**注意力**：每月 3 点，只约束"社交/情报类"动作（拜会、送礼、打听、赴宴、求情），避免"一天见十个人"。
3. 天数用尽 → 本月结束；玩家可"提前结束本月"（把剩余天数用于休养，回健康）。
4. 行动进行中可被打断：`interrupts` 队列在行动结算后检查，触发一条处境卡（"你在路上收到一封信"）。

### 3.3 耗时表（基准值，可按地区/路况修正）

| 动作 | 天数 | AP | 备注 |
| --- | ---: | ---: | --- |
| 贩货（单程） | 商路 `days`（4–12） | 0 | 取消"瞬移套利"，价格按**抵达日**结算 |
| 搬迁 | 商路 `days` | 0 | 到达后触发沿途见闻 |
| 拜会 / 求见 | 2 | 1 | 需要同地 |
| 送礼 | 1 | 1 | 需要同地 |
| 打听 | 3 | 1 | 见 S5 |
| 考察市场 | 2 | 1 | 情报 90 天 |
| 赴宴 / 上朝 | 1 | 1 | 见 S6 |
| 训练 | 30 | 0 | 整月投入，不能兼做他事 |
| 谋职 / 游说 | 7 | 1 | 见 S6 |
| 养病 | 15 | 0 | 健康 +25 |
| 出征 | 60 | 0 | 见 S7 |
| 组织/股份类 | 1–3 | 1 | **补上现在 0 AP 的漏洞** |

### 3.4 为什么这样就有取舍

30 天只能容纳"一次远行 + 两件小事"或"一次苦修"或"五场社交"。玩家第一次必须回答：**这个月我放弃什么？**

### 3.5 落地要点

- `CommandResult` 增加 `days: number`（替代只给 `travelDays` 的 UI 调用），`GameEngine.dispatch()` 成功后统一 `advanceDays(days)`；UI 的 `deps.advanceDays` 调用删除（`PlayerPanel.ts:278`、`RegionPanel.ts:252`）。
- 时间推进后需要重新检查 `pendingChoices` 与 `stopAtChoices`——即"行动被中途打断"。
- 回归护栏：`hash()` 必须仍可复现；`advanceDays` 的逐日结算不变。

## 4. S2 议程系统（处境）

### 4.1 定义

一条议程 = **一件有人在乎、有期限、有后果的事**。

它有三个必备字段：`谁在等`（来源）、`还剩几天`（期限）、`不做会怎样`（过期效果）。

### 4.2 数据结构

```ts
export type AgendaOrigin = 'debt' | 'rival' | 'office' | 'family' | 'ambition' | 'world';

export interface AgendaOption {
  readonly id: string;
  readonly label: string;          // ≤ 12 字
  readonly days: number;           // 耗时
  readonly ap?: number;
  readonly cost?: number;          // 铜币
  readonly check?: ChoiceCheck;    // 复用现有检定
  readonly hint: string;           // 代价/收益，必须是事实而非推荐
  readonly effects: readonly Effect[];
  readonly failureEffects?: readonly Effect[];
  readonly requires?: Expr;        // 复用现有条件表达式
}

export interface Agenda {
  readonly id: string;
  readonly origin: AgendaOrigin;
  /** 谁在等：人物/组织/国家/家族。 */
  readonly from: { scope: EntityScope; id: EntityId; name: string };
  readonly title: string;          // ≤ 16 字，"钱庄催款"
  readonly body: string;           // ≤ 60 字，必须含专名与"要什么"
  readonly openedDay: number;
  readonly dueDay: number | null;  // null = 无期限（背景）
  /** 过期未处理：通常是"别人得手"，不是扣钱。 */
  readonly expiry: readonly Effect[];
  /** 过期后是否升级为后果议程。 */
  readonly escalateTo?: string;
  readonly options: readonly AgendaOption[];
  /** 0 传闻 / 1 听说 / 2 确证（见 S5）。 */
  readonly certainty: 0 | 1 | 2;
  /** 同屏优先级：紧急 0，背景 1。 */
  readonly rank: 0 | 1;
}
```

### 4.3 生成规则（每月 1 日）

按顺序取，直到凑满 **3 条紧急 + 2 条背景**：

1. **到期承诺**（S4）：7 天内到期的借贷/许诺，必上紧急。
2. **对手行动**（S3）：每个对手每 2–3 个月产出 1 条可反应的议程。
3. **职务义务**（S6）：任职者每月 25% 概率收到"分内事"（查账、巡边、断案）。
4. **家族事务**（S8）：议亲、继承、病重、争产。
5. **野心机会**（S6）：与当前野心阶梯相关的机会（官位空缺、货路断供、战功）。
6. **世界请愿**（S9）：内容事件转成的"有人求你做某事"。

### 4.4 关键设计约束

- **不给推荐**。选项只写事实代价：`还 600 铜，关系 +1` / `只还 300，展期 30 天，关系 -1`。
- **必须能"什么都不做"**。忽略是合法选择，但会被记录并在月末结算（这是压力的来源）。
- **同一屏不超过 5 条**，其余进"风向"列表（可展开，纯文本）。
- **每条议程必须有名字**：「钱庄掌柜玛拉」而不是「势力 A」。

### 4.5 过期语义（这是重点）

过期不是"扣 200 铜"，而是让世界往前走一步：

| 来源 | 过期效果 |
| --- | --- |
| 债务 | 利息翻倍 + 债权人把你的名字报给商会（信用 -10） |
| 对手 | 对手完成他的目标（抢走席位/抬走货路/挖走伙计） |
| 职务 | 上司记一笔（晋升评分 -0.05），连续两次被免职 |
| 家族 | 关系下降一级，子嗣倾向偏移 |
| 野心机会 | 机会消失，且同类机会冷却 180 天 |

实现上，**过期效果尽量落在实体字段上**（席位归属、股份比例、关系值、信用分），不要只落在玩家钱包上——玩家要能看见"世界变了"。

### 4.6 与现有代码的接口

- `pendingChoices` 现在是"事件抉择"，保留；议程是它的**超集容器**，建议新增 `state.agendas`，并让 `App` 的弹窗只处理"紧急议程"，背景议程进面板。
- 复用 `ChoiceCheck` / `Expr` / `Effect`（`src/core/schema/defs.ts:165-172`），不新造效果语言。
- 新效果类型（见 S9）：`grant_office` / `relation` / `pledge` / `reveal` / `spawn_rival`。

### 4.7 S2b 计划：玩家主动的那一半

**为什么必须有**：议程解决"世界找你"，但不解决"你想干什么"。现在的玩家没有可表达意图的接口——`suggestGoals` 给什么就做什么。计划系统是玩家第一次能说"我要在三年内把这条商路吃下来"。

**定义**：一个跨越多月、分阶段、可能被抢走的项目。它是**结构性收益**（持续产出、解锁动词、改变地位），不是一次性奖励。

```ts
export type SchemeKind =
  | 'route'        // 开商路：完成 → 每月被动收入 + 该线价格情报
  | 'shop'         // 盘店铺：完成 → 本地零售利润 + 一个店员位
  | 'mill'         // 建磨坊：完成 → 该区粮价成本 -10%
  | 'school'       // 办学：完成 → 每年产出 1 名可招募人才
  | 'guard'        // 募私兵：完成 → 影响力 +，可镇压/护送
  | 'faction'      // 结党：完成 → 可托人谋职、投票、弹劾
  | 'alliance';    // 结亲：完成 → 姻亲家族的人情与兵援

export interface Scheme {
  readonly id: string;
  readonly kind: SchemeKind;
  readonly regionId: RegionId;
  /** 已完成阶段 / 总阶段（3–6）。 */
  readonly stage: number;
  readonly stages: number;
  /** 每阶段：天数 + 铜币 + 可能需要的技能检定。 */
  readonly costPerStage: { days: number; cash: number; skill?: { key: string; min: number } };
  /** 每完成一阶段付一次钱、占一段天数。 */
  readonly invested: number;
  /** 对手是否盯上了它（见 S3），0–1。 */
  readonly contested: number;
  /** 被抢走的进度：每次对手干扰 -1 阶段（不低于 0）。 */
  readonly interrupted: number;
}
```

**规则**

1. 同时最多 **2 个**计划（"专注"约束，强迫取舍）。
2. 每阶段消耗天数与现金，**与议程抢同一个 30 天预算**——这是核心张力：`还债` 与 `修商路` 不能同时做完。
3. 中断不销毁：进度保留，但每月衰减 5%；被对手盯上时（`contested > 0.5`）每次 tick 有 20% 概率 -1 阶段。
4. 完成时写历史、给称号，并改变后续议程的**类型**（例：有了商路 → 出现"商队被劫"议程；有了私兵 → 出现"邻国招揽"议程）。
5. 计划是**野心的具体化**：每条野心阶梯绑定 1–2 个计划种类，完成计划推进野心进度（不再是"钱够了就满"）。

**为什么这解决了"目标只是进度条"**

野心 = 方向；计划 = 手段；议程 = 阻力。三者共用一个 30 天预算，成长就变成"我在阻力下坚持做成了什么"，而不是"我的数字变大了"。

## 5. S3 对手系统

### 5.1 为什么必须有对手

现在世界上 75 个角色都在"自己过日子"，没有一个人**想要你手里的东西**。没有对手，就没有失败；没有失败，所有选择都等价。

### 5.2 对手是谁

3–6 个有名有姓、有目标的 NPC，来源三档：

- **内容指定**：每个国家 1–2 个（`content/rivals.json`），有名字、动机、初始资源。
- **系统生成**：玩家抢了谁的席位/货路，谁就变成对手（记仇）。
- **继承生成**：父辈的仇人继续找你（跨代压力）。

### 5.3 数据结构

```ts
export interface Rival {
  readonly characterId: CharacterId;
  /** 他要什么。 */
  readonly goal: 'office' | 'shares' | 'route' | 'contract' | 'revenge' | 'marriage';
  readonly targetId: string | null;
  /** 0–1：他离目标还有多远。到 1 就"得手"。 */
  progress: number;
  /** 对你的态度：-100 恨之入骨 … 100 盟友。 */
  stance: number;
  /** 记忆：最近 5 件你做过的事。 */
  readonly memory: readonly { day: number; kind: 'help' | 'harm' | 'betray'; note: string }[];
  /** 他的手段：0–1，影响他能不能成功。 */
  readonly cunning: number;
  /** 主动行动冷却。 */
  nextMoveDay: number;
}
```

### 5.4 每月 tick（确定性随机，流名 `rival:${characterId}`）

```
if 今天 < nextMoveDay: return
按 goal 评估 progress（与目标实体的当前状态比）
roll(0..1):
  < cunning*0.5      → 明着来：直接竞争（抬价/抢席/挖人），产出可见议程
  < cunning*0.85     → 暗着来：散布传言/伪造把柄，先产生"风声"（certainty 0）
  else               → 观望：progress +0.02，无可见影响
progress += 0.06~0.12（取决于玩家是否在反制）
如果 progress ≥ 1 → 执行得手 + 写历史 + 解锁"复仇"议程
```

玩家反制手段与效果：

| 手段 | 代价 | 效果 |
| --- | --- | --- |
| 打听 | 3 天 | 揭示对手下一步（certainty 0→2） |
| 拜会/送礼 | 1–2 天 + 钱 | stance +10~20；高于 40 时他暂停行动 6 个月 |
| 抬价竞争 | 钱 | progress -0.15，但你的现金 -15% |
| 揭发 | 需要证据（打听获得） | progress 归零、stance -50，失败则自己声望 -10 |
| 让他破产 | 长期 | 结束这条对手线，但引来他的盟友 |

### 5.5 反馈节奏

对手必须**可被感知**：每次行动产生一条信号（低确信度："有人在打听你的货路"），并把一条议程推进玩家视野。这是"世界在找你"的主要载体。

### 5.6 与现有系统的耦合

- 席位竞争复用 `Offices.applyForOffice` 的评分比较（`src/systems/country/Offices.ts:271-275`）。
- 股份竞争复用 `Shares`（对手按估值 1.1–1.3× 出价，玩家可选择跟价）。
- 关系影响复用 `Relations.ts`（stance 是 `Relation` 的玩家视角镜像，避免两套数据）。

## 6. S4 承诺与债务

### 6.1 为什么需要

现在所有"欠"都会自动消失：`Upkeep` 扣到 0 为止（`src/systems/character/Upkeep.ts:23-29`），合约违约有罚金但没有记忆。没有记忆，就没有信誉；没有信誉，"守约"这个美德没有价值。

### 6.2 数据结构

```ts
export interface Pledge {
  readonly id: string;
  readonly kind: 'loan' | 'promise' | 'duty' | 'levy' | 'marriage';
  /** 对谁许的。 */
  readonly to: CharacterId;
  readonly amount: number;
  readonly openedDay: number;
  readonly dueDay: number;
  readonly onFulfil: readonly Effect[];
  readonly onDefault: readonly Effect[];
  /** 是否已被宽限过一次。 */
  readonly graceUsed: boolean;
}
```

### 6.3 规则

- 借钱/放贷、许诺投票、答应出兵、答应在 X 日前交货、答应婚事——都写 `Pledge`。
- 到期前 7 天自动生成一条紧急议程（这就是 S2 的第一优先级来源）。
- **违约有信用分**：`meta.credit`（0–100），违约 -15，履约 +3。信用分影响借贷利率、能否赊账、能否谋职。
- 信用分 <30 时：商人要现款、钱庄拒贷、部分议程直接不给你看（"没人愿意跟你谈"）。

### 6.4 为什么这会让人紧张

因为它把"未来的自己"变成了债主：玩家必须同时管理**当下的现金**和**未来的义务**。这是模拟经营最经典的张力，而现在的版本完全没有。

## 7. S5 情报与确信度

### 7.1 现状

世界对玩家是全透明的：所有市场价、所有组织现金、所有人物属性都能直接看到。于是"打听"（`gossip`）没有存在意义——它已经是死动词。

### 7.2 规则

1. 每个"非亲见"的数字带确信度：**0 传闻 / 1 听说 / 2 确证**。
2. 面板显示：确信度 2 显示精确值；1 显示区间（±25%）；0 灰显并标"未核实"。
3. 打听（3 天 + 20 铜）对**一个对象**（人/组织/国家/市场）做一次升级，持续 90 天。
4. 亲眼所见（到访该地区、与本人会面）自动置 2。
5. 对手的"暗着来"会**降低**你对相关对象的置信度（传言污染）。

### 7.3 为什么这是核心而非装饰

它把"最优解"从"可算"变成"可赌"：玩家在信息不全时做判断，事后才知道对不对——这正是决策感的来源。

### 7.4 落地

- 复用 `state.inspections`（现在是 `regionId → 到期日`，`src/core/commands/personal.ts:365`），扩成 `state.intel: Record<string, { level: 0|1|2; until: number }>`。
- UI 渲染层加 `renderValue(value, certainty)`，纯函数，放 `ui/format.ts`。

## 8. S6 阶梯与解锁

### 8.1 问题

职业 4 级、5–8 年封顶；官职 3 席、评分上限 0.39 < 门槛 0.45（详见诊断 P3），仕途整条线关着。

### 8.2 职业：4 → 6 级，每级解锁一个动词

| 级 | 头衔 | 门槛（钱 / 主技能） | 解锁 |
| ---: | --- | --- | --- |
| 0 | 学徒 | 0 / 0 | — |
| 1 | 伙计 | 800 / 3 | 赊账（信用 +10） |
| 2 | 行商 | 4,000 / 6 | 雇伙计（1 人，替你跑一趟） |
| 3 | 商会主 | 12,000 / 9 | 开商路（组织级） |
| 4 | 行业巨头 | 40,000 / 12 | 定价权（局部市场 ±10%） |
| 5 | 一方巨擘 | 120,000 / 15 | 派系（可托人谋职/投票） |

每级同时提升"承载力/让利/信用上限"，让成长有形状而不只是数字变大。

### 8.3 官职：6 席 × 3 品，一人一席

- 席位：首相 / 财政 / 军务 / 司法 / 礼宾 / 地方总督。
- 品阶：书吏（0）→ 议员（1）→ 大臣（2）。同一席位逐级晋升，不是一次到位。
- **评分公式修正**：`技能 0.45 + 财富 0.20 + 声望 0.20 + 人脉 0.15`，去掉"必须有官职才有影响力"的死循环；影响力量改由"席位 + 派系 + 声望"计算。
- **任命有三条路**：谋求（评分够 + 席位空缺/压过在任）、举荐（有人情/盟友）、功绩（战功/赈灾）。三条路给出不同的玩法切片。
- 门槛全可见：面板显示"你的评分 39 → 需要 45（技能 22 / 财富 8 / 声望 5 / 人脉 4）"。

### 8.4 军事：把锁死的 4 个命令接上

`declare_war` / `levy_army` / `march_army` / `offer_peace` 需要 `influence ≥ 0.4`，而影响力死锁在官职上。修好 8.3 后自然解锁；额外提供"随军"（不需要权柄，作为幕僚/队长参战，可阵亡）作为低阶入口。

## 9. S7 代价与失败

### 9.1 三条失败线

| 线 | 触发 | 后果 | 可挽回 |
| --- | --- | --- | --- |
| 健康 | 45 岁后逐年风险；健康 <20 时 +5%/月 | 重病→死亡 | 养病/延医（花钱） |
| 债务 | 现金 <0 且宽限 3 个月 | 资产查封、信用崩、被追债 | 变卖资产/借新还旧/谈判 |
| 战争 | 随军或亲自出战 | 8% 阵亡 | 不去 |

### 9.2 原则

- **失败必须可预判**：任何时候，玩家都能在面板上看到"你还有几个月"。
- **失败要有体面的收束**：不是 Game Over 黑屏，是讣告 + 结算（见 S10），并允许以继承人或新人物继续。
- **不要"突然死亡"**：所有致死路径都有 1–2 次警告（议程："你咳了三个月"）。

### 9.3 现有代码

- `mortalityRisk` 45 岁前恒 0（`src/systems/character/CharacterSystem.ts:83-86`）→ 改为 40 岁起缓升，并把健康接入死亡判定。
- `Upkeep` 的 `Math.min(player.wealth, fee)`（`Upkeep.ts:26`）→ 允许 `wealth < 0`，进负债状态。

## 10. S8 关系、家族、继承

### 10.1 关系要"有用"

现在 `Relations.ts` 只被 UI 读取（诊断 P5）。v3 里关系必须进入结算：

- 谋职评分的人脉项；
- 契约谈判的折扣；
- 议程里"他会帮你吗"的条件；
- 背叛/揭发的成功率。

### 10.2 六个关系等级

陌生 → 相识 → 相熟 → 盟友 → 挚友 → 生死之交（负向同理：嫌隙 → 敌意 → 仇敌）。

每级解锁一个互动：打听对方情报、托付代办、借钱、联姻、共谋、托孤。

### 10.3 家族与继承

- 婚姻（`marry`）：带来人脉与子嗣，也带来姻亲的义务。
- 教养（`raise_heir`）：每 5 年可投入 1 次，决定继承人的属性倾向与野心。
- 继承：玩家死亡时，从成年子嗣中选一个（不是你死后系统随机挑），继承 60% 资产 + 全部家族声望 + 一半人情；**债务也继承**。
- 无嗣：王朝终结卡（一次评分，然后开新局）。

### 10.4 跨代目标

家族声望（`meta.houseRenown`）是跨代累积的第二分数。它让"这一代没做成"也有意义——你可以为下一代铺路（买地、结亲、送学）。

### 10.5 人情账本：第三种货币

现在的游戏只有一种货币（铜币），所有选择都能折算成钱，于是选择本质等价。v3 引入两种不可直接购买的资源：

| 货币 | 来源 | 用途 | 转换关系 |
| --- | --- | --- | --- |
| 铜币 | 经营 | 买货、买股、行贿 | 基础 |
| **人情** | 帮人、送礼、履约 | 托人谋职、免息借款、换确切情报、撑场面 | 钱只能缓慢换人情（送礼有冷却），人情换不来钱 |
| **声望** | 任职、赈灾、战功、公开事迹 | 谋职评分、联姻门槛、事件选项、继承评级 | 声望只能靠公开行为，无法购买 |

```ts
export interface Favor {
  readonly characterId: CharacterId;
  amount: number;        // 0–5
  readonly note: string; // "他儿子病时你借过钱"
}
```

- 人情 +1：帮一次忙 / 送礼（同一人 6 个月冷却一次）/ 履约 +2。
- 人情 -1 并归零的用法：托人谋职（3）、免息借款（2）、换一条确切情报（1）、婚礼撑场面（1）。
- **花掉后关系 -5**："我欠你的，还清了"——人情是消耗品，不是存款。这让"用谁的人情"成为长期决策。

三种货币的存在，让"钱多"不再等于"什么都能做"：你可能很有钱，但没人愿意替你说话。

## 11. S9 内容 2.0：从"广播"到"请愿"

### 11.1 现在的 90 条事件是广播

65/90 是 `country` scope（别国的事），只有 11 条有选项，38 个选项效果全是数值加减，正文中位数 29 字。

### 11.2 新形态：请愿（Petition）

一条内容事件的默认形态是：**一个有名有姓的人，向玩家要一件具体的事，给出具体代价**。

```jsonc
{
  "id": "ev_pet_maras_debt",
  "domain": "local",
  "scope": "character",
  "requires": { "debtOver": 0, "relationMin": { "c_mara": -10 } },
  "text": {
    "title": "钱庄掌柜玛拉上门",
    "body": "玛拉把账本摊在柜台上：'六百铜，三月八日之前。交不上，我就把你这半年的流水给商会看。'"
  },
  "choices": [
    {
      "id": "pay",
      "label": "当场还清",
      "days": 0,
      "effects": [{ "kind": "add", "path": "wealth", "value": -600 },
                  { "kind": "relation", "target": "c_mara", "value": 8 }]
    },
    {
      "id": "beg",
      "label": "求她宽限",
      "days": 1,
      "check": { "attribute": "charisma", "difficulty": 12 },
      "effects": [{ "kind": "pledge", "to": "c_mara", "days": 30, "amount": 600 },
                  { "kind": "relation", "target": "c_mara", "value": -6 }],
      "failureEffects": [{ "kind": "add", "path": "meta.credit", "value": -10 }]
    }
  ]
}
```

### 11.3 Schema 扩展（v13）

新增效果类型（都在 `src/core/schema/defs.ts` 的 `Effect` 联合里）：

| kind | 作用 |
| --- | --- |
| `relation` | 改变两个角色的关系 |
| `pledge` | 建立承诺/债务 |
| `grant_office` | 授职（含品阶） |
| `reveal` | 提升某对象的情报确信度 |
| `spawn_rival` | 生成对手 |
| `agenda` | 手动排入一条议程 |

新增事件字段：`requires`（玩家状态条件：负债/任官/有对手/关系等级/声望区间）、`certainty`（传闻型）、`choices[].days`。

### 11.4 内容配额（不排期，只定标准）

| 类别 | 现在 | v3 目标 |
| --- | ---: | ---: |
| 事件总数 | 90 | **400** |
| 带选项 | 11 | **≥ 160**（40%） |
| 请愿型（对人） | ~9 | **≥ 200** |
| 议程模板 | 0 | **60** |
| 对手原型 | 0 | **20** |
| 每国本地事件 | ~5 | **≥ 8** |
| 文本长度 | 中位 29 | 中位 **45–60**，必须含专名 + 一个可执行信息 |

### 11.5 文本规范（可测）

1. 每条正文 ≤ 60 字，且必须包含**一个专名**（人/地/组织）。
2. 每个选项 `label` ≤ 12 字，`hint` 写代价与收益，不写推荐。
3. 禁止"国库为此支付了一笔开销"这类无数值、无对象、无后果的句子。
4. 结果写人话：`你花了 40 铜，换回一句承诺`，而不是 `wealth: 1683 → 1643`。

### 11.6 内容生产：模板 + 槽位，而不是 400 张手写卡

手写 400 条事件不可持续，也没必要。真正需要手写的是**冲突**，不是**名字**。

**模板化**

```jsonc
{
  "template": "debt_collector",
  "slots": {
    "creditor": { "from": "characters", "filter": { "hasFavor": false }, "pick": "highestWealth" },
    "region":   { "from": "player.location" },
    "amount":   { "calc": "clamp(player.debt * 0.4, 150, 1200)" },
    "dueDays":  { "values": [7, 10, 14] }
  },
  "text": {
    "title": "{creditor.name}来讨债",
    "body": "{creditor.name}把账本摊开：'{amount} 铜，{dueDays} 天之内。'"
  }
}
```

一份模板 × 槽位组合 = 6–25 个具体实例。**400 条实际内容 ≈ 70 个模板**，且能随玩家状态自我适配。

**覆盖矩阵（必须填满）**

6 种处境（负债 / 任官 / 有对手 / 有家族 / 出征 / 被诬告）× 4 个主要国家 × 3 个生涯阶段（早期 / 中期 / 高位）= 72 格，每格 ≥ 3 条。

**校验器**

新增 `scripts/content-lint.mjs`，在 CI 里跑：

- 正文 ≤ 60 字，且至少含一个专名槽位；
- 每个选项有 `label` 与 `hint`，`hint` 不含"推荐/最佳/应该"；
- 效果路径必须存在于 schema（复用 `validateWorld` 的路径表）；
- 条件的 `requires` 必须至少在一个可达状态下成立（防止写了永远不触发的内容）；
- 统计每个 template 的实际触发次数（`sim` 报告），长期为 0 的模板报警。

**为什么这比堆量重要**

现在的 90 条事件里，65 条是别国的广播——量大但不落在玩家身上。模板化之后，同样的写作量可以生成 3 倍的"对玩家的请愿"，而且每条都有名字、有期限、有代价。

## 12. S10 终局：一生结算

### 12.1 死亡不是暂停

现在的讣告只有一行现金与组织名（`src/ui/app/lifecycle.ts:42-74`），"落幕"只是暂停（`:76-81`）。v3 的死亡是一次**评分**：

**结算页内容**

```
终年 61 岁 · 行商 · 无官职
净资产 78,127 铜（全生涯曲线）
影响过的人 12（其中 3 人因你而死）
未了之事 2（玛拉的债、季莫的席）
评级 B：你富了，但没人在你的葬礼上提起你的名字。
```

### 12.2 评级算法（可调，但必须可解释）

```
score = 0.35 * 净资产分 + 0.25 * 目标完成度 + 0.25 * 声望 + 0.15 * 遗产延续
```

- 净资产分：`log10(wealth)/log10(200000)`，封顶 1。
- 目标完成度：野心阶梯 + 家族声望。
- 声望：国家级声望均值。
- 遗产延续：有继承人且继承人起点 ≥ 你起点的 1.5×。

### 12.3 三种结局

| 结局 | 条件 | 收束 |
| --- | --- | --- |
| 王朝 | 有继承人且声望 ≥ 60 | 继承模式，债务与人情一并继承 |
| 落幕 | 有继承人但声望 < 60 | 继承，但起点降级（资产 40%，声望减半） |
| 终结 | 无继承人，或破产+负债超额 | 王朝终结卡，全生涯评分，开新局 |

- 模态每**月最多 1 张**（紧急议程），其余进面板。
- 抉择卡与历史卡合并（诊断 P6 的重复问题）。
- 见闻卡移出模态，进"风向"。
- 所有模态都可以"稍后处理"（进处境板），不再强制打断快进。

### 13.3 快进

30× 下不再弹模态，只在**紧急议程**出现时暂停一次；提供"处理完这月剩余天数"的一键快进。

## 14. 节奏与数值预算

### 14.1 决策密度目标

| 时间尺度 | 现在 | v3 目标 |
| --- | ---: | ---: |
| 每月有代价的选择 | 0.2–0.6 | **3–5** |
| 每年被迫取舍 | ~7 | **40–50** |
| 10 年"差一点失败" | 0 | **≥ 3** |

### 14.2 内容消耗

### 14.3 参数总表（建议初始值）

| 参数 | 值 | 位置 |
| --- | --- | --- |
| 每月天数 | 30 | `GameClock` |
| 每月注意力 AP | 3 | `Activity.ts` |
| 同屏紧急议程 | 3 | 新 `AgendaEngine` |
| 背景议程 | 2 | 同上 |
| 对手数 | 3–6 | `state.rivals` |

| 对手得手进度 | +0.06~0.12/次 | 同上 |
| 情报衰减 | 90 天 | `state.intel` |

| 违约信用惩罚 | -15 | `meta.credit` |
| 45 岁后死亡率 | 1.09^(age-45)/200 | `mortalityRisk` |
| 随军阵亡率 | 8% | `WarSystem` |

### 14.4 难度曲线：压力随玩家变强而变强（但不作弊）

一条模拟游戏最常见的死法：前期太难、中期太易、后期无事。v3 用**对手压强**做橡皮筋，而不是给 NPC 加隐藏数值。

```ts
// 目标压强：玩家越强，世界对他的索求越多（只在生成侧调整，不改结算）
function pressureTarget(player: Character, rank: number): number {
  const wealthTier = Math.min(3, Math.floor(Math.log10(Math.max(1, player.wealth) / 1500)));
  return 0.15 + 0.12 * wealthTier + 0.08 * player.offices.length + 0.05 * rank;
}
```

| 阶段 | 年 | 局面 | 对手 | 每月议程 | 玩家感受 |
| --- | ---: | --- | ---: | ---: | --- |
| 学习 | 1–5 | 只有一个债主和一个同行 | 1 | 3 | 犯错有代价，但不致命 |
| 竞争 | 6–15 | 席位与货路开始有限 | 2 | 3–4 | 有人和你抢同一件事 |
| 权力 | 16–30 | 职务义务、派系、战争 | 3–5 | 4–5 | 时间永远不够 |
| 传承 | 30+ | 死亡临近、继承人、家族 | 3–5（含继承仇怨） | 4 | 你在为下一代布局 |

**三条配平原则**

1. 压强只影响"世界向你索取多少"，不直接改玩家数值（避免作弊感）。
2. 任何时候都必须存在"体面撤退"选项：花大代价退出，但不出局。
3. 玩家的**计划**必须能在压力下推进——如果每次都被打断，压力就变成了挫败。经验值：计划每阶段被打断的概率 ≤ 25%。

### 14.5 一局 20 年的形状（五个节拍）

设计上要能一句话说出"这五年我在玩什么"。如果说不出来，说明这个阶段没有玩法。

| 节拍 | 年 | 玩家在做什么 | 世界在做什么 | 这一段的"新东西" |
| --- | ---: | --- | --- | --- |
| 立身 | 1–4 | 还债、跑货、盘下第一个铺面 | 债主与同行各一个，缓慢施压 | 计划系统进场；第一次被抢 |
| 结交 | 5–9 | 结亲、赴宴、还人情，第一次谋求公职 | 席位出现空缺，对手开始站队 | 人情与声望进场；谋职评分可见 |
| 入场 | 10–15 | 上任、结党、开商路、与对手正面竞争 | 派系斗争、政策变动、第一次战争 | 官职义务议程；派系投票；随军 |
| 守成 | 16–24 | 在任上做事、镇压/赈灾、教子 | 王朝更替、邻国崛起、旧对手复仇 | 继承仇怨；健康开始下滑；家族声望 |
| 交班 | 25–30 | 安排婚事、立遗嘱、把人情交给孩子 | 你的时代结束，年轻人上位 | 死亡结算；继承；下一代开局 |

**每一段都必须有"只有这一段能做"的事**（计划种类、社交层级、职务权限、继承安排），否则玩家会觉得 20 年在重复同一件事——这正是当前版本的病灶。

### 15.5 引擎接口草案（实现时以此为准）

```ts
// 只读查询（UI 可调，纯函数，铁律 1 的既定例外扩展到这里）
class GameEngine {
  agendas(): readonly Agenda[];              // 当前处境，按 rank/剩余天数排序
  schemes(): readonly Scheme[];              // 当前计划
  pledges(): readonly Pledge[];              // 我的承诺
  intel(scope: EntityScope, id: string): { level: 0 | 1 | 2; until: number };
  standing(countryId: string): { score: number; parts: { skill: number; wealth: number; renown: number; ties: number }; gate: number };
}

// 写入口（全部走 dispatch，命令扩展 Command 联合）
type NewCommand =
  | { kind: 'resolve_agenda'; agendaId: string; optionId: string }
  | { kind: 'start_scheme'; schemeKind: SchemeKind; regionId: RegionId }
  | { kind: 'advance_scheme'; schemeId: string }          // 投入一个阶段
  | { kind: 'inspect'; scope: EntityScope; id: string }   // 打听/核查，3 天
  | { kind: 'pledge'; to: CharacterId; kind: PledgeKind; amount: number; dueDays: number }
  | { kind: 'call_favor'; to: CharacterId; use: 'office' | 'loan' | 'intel' | 'show' }
  | { kind: 'end_month' };                                // 提前结束本月，剩余天数转休养
```

**实现顺序倒推**：`resolve_agenda` 与 `start_scheme` 是骨架，先做这两个就能验证循环；`call_favor` 与 `advance_scheme` 是第二阶段。

**与现有命令的关系**：`seek_office`、`gift`、`gossip`、`trade_goods`、`move` 全部保留，但都要补 `days` 成本并接入议程/人情。

## 17. 怎么验证"真的变好玩了"

**定性（盲测，最重要）**

给 3–5 个没读过代码的人玩 20 分钟，然后问三个问题：

1. 你现在在做什么？为什么？
2. 如果这个月什么都不做，会发生什么？
3. 你下一步最怕什么？

如果答案里有**具体的人名、天数、后果**，方向就是对的；如果只有"我在赚钱"，就是没成。

**定量**

| 指标 | 现在 | 目标 |
| --- | ---: | ---: |
| 每月有代价的选择 | 0.2–0.6 | ≥ 3 |
| 玩家主动操作/月度 | 3（全是同一类） | 3–4（类型分散） |
| 10 年新解锁动词 | 0 | ≥ 4 |
| 10 年完成的计划 | 0 | ≥ 2 |
| 10 年"差一点失败" | 0 | ≥ 3 |
| 弹窗中"与上月逐字相同" | 47% | < 10% |
| 30 年官职 | 0 | ≥ 1，且第 10 年前可及 |
| 左栏整栏滚动条 | 必然出现 | **0**（1440×900 与 1280×800） |
| 首屏可交互元素 | 30+ | ≤ 20 |
| 20 年内完成的继承 | 0（无路可走） | 1 次完整跨代 |
| 少东家开局合法性 | 不存在 | 0.40–0.60 |

**放弃条件（诚实版）**

如果 M1+M2 做完后，盲测里玩家仍然说不出"我在等什么"，说明"处境驱动"这个方向在这个题材上不成立，应转回"叙事驱动"（固定剧本 + 多结局），而不是继续加系统。

## 18. 风险与反例

这一章是给"做出来之后不好玩"准备的清单。每条都写了**症状**和**立即纠偏动作**。

### 18.1 压力系统退化成待办清单（最大风险）

- 症状：玩家每天在 5 条议程之间来回点，感觉像上班；忽略一条也没有真实后果。
- 纠偏：① 同屏紧急议程硬上限 3，超出自动降级为背景；② 背景议程**绝不惩罚**；③ 必须有"这月什么都不做"的安全线（把 30 天花在休养/陪家人，剧情照走）；④ 每条议程的过期效果必须落在**可见的实体**上（谁拿走了席位、谁搬进了你的铺面），而不是"扣 200 铜"。

### 18.2 挫败过载

- 症状：连输三次后玩家关掉游戏，且说不出"我本可以怎么做"。
- 纠偏：所有失败路径必须满足**可预判**（面板显示倒计时）与**有第二次机会**（宽限、谈判、变卖）；首次致命失败前必须有 2 次警告议程；每个崩溃局面提供一个"体面撤退"选项。

### 18.3 系统过多，玩家学不会

- 症状：新手 20 分钟看不懂"人情/声望/信用/确信度"四个新概念。
- 纠偏：新概念**按需出现**——人情在第一次有人帮你时出现，声望在第一次谋职时出现，确信度只在你看不到的数上出现。开局 30 分钟只允许 3 个概念：钱、时间、某人要你做的事。

### 18.4 内容与系统错配

- 症状：写了 200 条事件，但 `requires` 永远不满足，玩家一条都没见过。
- 纠偏：`content-lint` 强制统计触发率（见 11.6）；`sim` 报告输出"每个模板 10 年触发次数"，长期为 0 即视为死内容，CI 报警。

### 18.5 确定性破功

- 症状：同种子两次跑出不同哈希，R1 测试红。
- 纠偏：所有新生成走命名流（`rival:${id}`、`agenda:${day}`、`scheme:${id}`）；禁止在生成逻辑里读 `Date.now()` 或 `Object.keys` 顺序；新增一张"生成器 → 流名"对照表放进 `Random.ts` 注释。

### 18.6 玩家仍然被动

- 症状：玩家每月只回答议程，从不主动发起任何东西。
- 纠偏：这是 S2b 存在的理由。验收时单独测一个指标——**10 年内完成的计划数 ≥ 2**。如果玩家从不启动计划，说明计划的启动成本（找到入口、理解收益）太高，而不是玩家不想。

### 18.7 数值通胀复发

- 症状：30 年后钱又变成天文数字，物价与收益脱节。
- 纠偏：所有结构性收益（商路、磨坊、店铺）必须挂在**实体**上（地区、市场、组织），并受现有市场系统约束；禁止给玩家直接加被动现金，必须经由市场/组织账本。资产税与通胀侵蚀加入 `Upkeep`，让囤钱有成本。

### 18.8 单文件预算被撑爆

- 症状：`release/index.html` 超过 1.5 MiB，`pnpm release` 校验失败。
- 纠偏：内容用模板 + 槽位（11.6）而不是展开的 JSON；文本资源做 gzip 后内联；新增内容前跑一次 `pnpm build` 看体积。

## 19. UI 2.0：固定槽位 HUD

### 19.1 现状：左栏为什么一定会滚

| `base.css` 里 39 处 font-size ≤ 0.74rem（9.6–11.8px），低于可读下限 | `grep -cE "font-size: 0.(6[0-9]|7[0-4])rem" src/ui/styles/base.css` → 39；另见试玩报告 P2 |
| 小屏断点把面板改成整页滚动，处境会被推到屏外 | `base.css:1687-1733`（`.panel { overflow: visible }`） |

结论：**不是"信息太多"，是没有给信息分配固定位置**。同样是这些数字，放进固定槽位就不需要滚。

### 19.2 四条规则

1. **一屏装得下**：左栏高度 = 视口 − 顶栏 − 时间条；整栏 `overflow: hidden`，只有列表内部允许滚。
2. **顺序恒定**：槽位顺序不随内容变化。内容多了先截断、再内部滚、最后进"更多"，**绝不挪位**。
3. **数字带变化**：每个读数带 ↑↓ 与上月差（现在的数字全是绝对值，玩家感觉不到自己做了什么）。
4. **次要信息下沉**：信仰、归属、完整人物卡移出左栏；建议事项删除（由 §4 的处境替代）。

## 20. 继承与王朝 2.0：少东家开局

### 20.1 现状实测：玩家根本没有继承

| 观察 | 数据 / 证据 |
| --- | --- |
| 开局：无家族、无配偶、无子女、`heirs()` 返回 0 | 探针：`familyId: null, spouseId: null, 子女 0, 继承人 0` |
| 玩家会被系统**自动安排婚姻**，但既无选择也无提示 | 第 **10 年 12 月 30 日**，`艾伦·格雷（41 岁）与 阿黛拉·白鹿（48 岁）成婚`——只写了一条 `milestone` 历史；`Demography.ts:100-156` 的 `singles` 没有排除玩家，也没有征询 |
| 配对对象已过生育窗口，于是**永远不会有子女** | 女方 48 岁；`Demography.ts:162-166` 只让 `FERTILITY_AGE_MIN..MAX` 内的女性怀孕，而 `MARRIAGE_AGE_MAX = 50`（`demographyRules.ts:11`）——**婚配池比生育池宽 8 岁** |
| 配偶去世后 `spouseId` 被清空，家族只剩玩家一人与逝者 | 第 30 年：`familyId: fam_c_dynasty_005`、`spouseId: null`、`子女 0`、`继承人 0`、家族 2 名成员（1 活 1 故） |
| 家族 `prestige` 字段存在，但玩家家族恒为 0 | `src/core/schema/ids.ts:55-62`；探针输出 `声望 0` |
| 继承只是切换 `playerId`，不改财产、不扣合法性 | `GameEngine.continueAs`，`src/core/GameEngine.ts:141-158` |
| 遗产分割只在 NPC 年度结算里，玩家不参与 | `GameEngine.ts:560-574` |

**结论**：30 年实测里，玩家有 **1 次被动婚姻、0 个子女、0 个继承人**。
继承链在数据层就断了——不是数值调不好，是玩家没有家族生命周期。用户要的"少东家"，必须先把这条链（成家 → 养育 → 传位）建起来，而且必须**保证至少一条可行的继承人路径**，否则会再次死锁。

**附带发现的两个真 bug**：

1. 婚配池（≤50 岁）与生育池（≤42 岁左右）不重合，玩家可能像本局一样"结婚即绝后"。
2. 玩家的婚姻不产生任何玩家侧反馈（无议程、无提示、无选择），只在编年史里有一行。

### 20.2 四条目标

1. 玩家能**主动**成家、生子、教养、传位，而不是被动等系统安排。
2. 继承**有代价**：财产分割、合法性下降、债务全额继承。
3. 继承**有收益**：更高的起点（人脉、声望、技能底子、家族产业）。
4. 每次落幕都是一次**结算与选择**，不是黑屏。

### 20.3 生命周期四段

| 段 | 年龄 | 玩家在做什么 | 系统在做什么 |
| --- | --- | --- | --- |
| 成家 | 20–40 | 议亲、选门第、付聘礼 | 姻亲关系、嫁妆、可能结仇 |
| 养育 | 婚后–子嗣 16 岁 | 每 5 年一次教养取向 | 子嗣属性/倾向/关系 |
| 传位 | 55+ 或死亡 | 立遗嘱、选继承人、交班 | 争产判定、合法性结算 |
| 余荫 | 继承后 | 以少东家继续 | 前任变长老 NPC；人情/仇敌继承 |

### 20.4 成家：`marry`

- **条件**：≥16 岁、未婚、个人声望 ≥ 20、聘礼 200–2,000 铜（按门第）。
- **候选 3 人**：同城优先 → 同国；门第差 ≤ 30（家族声望）；显示对方的属性、家族、嫁妆、以及"这门亲事能带来什么"。
- **结果**：
  - 配偶入家族（`familyId` 合并或新建）；
  - 姻亲关系 +20，配偶家族的战时/政争可请求支援；
  - 嫁妆入账（100–800 铜），同时获得 1 个人情；
  - 与对手家族联姻可**暂时停战**（`stance +30`，见 §5.4）——这是把婚姻变成策略的关键。
- **代价**：聘礼、一个月的社交时间（§3 的天数），以及"选错门第"的长期后果（姻亲拖累）。

**修掉现状的两个 bug**

1. **婚配池必须与生育池对齐**：对玩家而言，候选必须处于可生育年龄（或明确标注"这门亲事不会有子嗣"并给玩家知情权）。现在的 `MARRIAGE_AGE_MAX = 50` 与生育上限不重合，才会出现"48 岁新娘 + 41 岁新郎 = 绝后"。
2. **婚事必须有反馈**：成婚写 `milestone` 之外，还要生成一条议程（"岳家请你赴宴"）与一个月报条目，而不是只在编年史里留一行。

**保底：立嗣（避免任何死局）**

如果玩家 45 岁仍无子嗣，开放三条路——**保证每一局都有继承可能**：

| 方式 | 条件 | 继承比例 | 合法性 |
| --- | --- | ---: | ---: |
| 收养 | 声望 ≥ 30，花 200 铜 | 正常继承的 80% | 0.40 |
| 过继旁支 | 家族内有 16+ 的侄/甥 | 100% | 0.45 |
| 收徒 | 组织内有忠诚成员，花 1 人情 | 60% | 0.35 |

立嗣本身会生成一条议程（"族老质疑你的安排"），给玩家一次公开表态的机会。

### 20.5 养育：`raise_heir`

- 每 5 年一次，最多 3 次（到 16 岁成年）。
- 三种取向，对应三条成长线：

| 取向 | 主技能 +1 | 倾向 | 成年后解锁 |
| --- | --- | --- | --- |
| 经商 | 贸易 / 估值 | 野心 fortune | 可继承商路与店铺 |
| 从政 | 说服 / 律法 | 野心 power | 合法性 +0.05 |
| 从军 | 格斗 / 战术 | 野心 renown | 可随军、战功加成 |

- 每次教养：子嗣关系 +10，父母各花 1 次行动力与 30 天（§3）。
- **完全不管**：子嗣属性随机，关系 -10——这是"忙事业"的真实代价。

### 20.6 少东家起点修正表（核心）

| 项 | 继承比例 | 说明 |
| --- | ---: | --- |
| 现金 | **60%** | 遗产税 20% + 丧葬 10% + 分割 10%；不是"白拿" |
| 股份 | **70%** | 其他股东有优先购买权，可能被阻挠（产生议程） |
| 房产/资产 | 100% | 但带抵押与维护费（每月固定支出） |
| 债务 | **100%** | 全额继承——这是压力的主要来源 |
| 家族声望 | 50% | 剩下的 50% 靠你自己挣 |
| 人情 | 50%（向下取整） | 父辈的朋友认你，但不欠你 |
| 盟友关系 | ×0.6 | 人情淡了，需要重新走动 |
| 仇敌 | **×1.0** | 仇怨全额继承，且对方知道你是谁 |
| 技能 | 30%（向下取整） | 耳濡目染，但没练过就是没练过 |
| 合法性 | 0.40–0.60 | 见 20.7：由父辈官职、家族声望与是否生前交班共同决定 |
| 年龄 | 子嗣实际年龄（16–30） | 由生育时间决定，不是凭空 20 岁 |
| 个人声望 | 0 | 你自己挣 |

**设计意图**：起点比新开一局高（有家族、有本金、有人脉、有现成产业），但每一项都打了折，且多背了一笔债和一批仇人。这就是"少东家"的味道——**看起来继承了一切，其实继承的是账单**。

### 20.7 合法性（legitimacy）：少东家的核心变量

新增 `Character.legitimacy`（0–1），与国家的 `legitimacy` 同名不同域，只属于个人。

**初值**：

```
legitimacy = 0.5
           + 0.15 × min(3, 父辈官职数)     // 父辈的公职背书
           + 0.10 × (家族声望 / 100)
           - 0.10 × (生前交班 ? 0 : 1)      // 死后继承无背书
```

**影响**：

| 用途 | 效果 |
| --- | --- |
| 谋职评分 | 新增 0.15 权重（§8.3 的公式里替换"影响力"项） |
| 借贷额度 | 上限 × legitimacy（低于 0.4 时钱庄拒绝） |
| 联姻门槛 | 对方家族要求 `你的合法性 ≥ 他们的声望/100 - 0.2` |
| 议程选项 | 部分选项需要 `legitimacy ≥ 0.5`（"以家主身份召集族人"） |
| NPC 服从 | 组织成员在你继承后 6 个月内可能不服（效率 -10%） |

**变动**：

| 事件 | 合法性 |
| --- | ---: |
| 公开赈灾 / 打赢一场官司 | +0.10 |
| 生前交班（父辈站台） | +0.10 |
| 遗嘱指定 | +0.05 |
| 违约 / 赖账被公开 | -0.10 |
| 争产失败 | -0.20 |
| 被弹劾 | -0.15 |

**低于 0.3 → 触发"合法性危机"议程**（政敌公开质疑你的继承权，要求分家或让位）。这就是少东家前两年的主要压力。

**高于 0.7 → 解锁"名正言顺"**：可以用一半的代价收编对手的盟友，或直接接管空缺席位。

### 20.8 兄弟与争产

- 多子嗣时选定继承人，其他兄弟：
  - 关系 **-30**；
  - **35%** 概率成为 `Rival`（`goal: 'revenge'`，见 §5.3）；
  - 100% 触发"争产"议程：
    - **分家**：给对方 20% 资产，换 10 年和平；
    - **收买**：花 300–800 铜 + 1 人情，对方暂时退出；
    - **打压**：声望 -10、对方变死敌，但保全部财产。
- **遗嘱**（50 铜）：争产概率减半，且合法性 +0.05。
- 这给了继承"不是白拿的"机制，也让"多子"从好事变成需要管理的麻烦。

### 20.9 三种传位方式

| 方式 | 条件 | 合法性 | 备注 |
| --- | --- | --- | --- |
| 生前交班 | 55 岁+，继承人 16 岁+ | +0.10 | 前任变"家族长老"NPC：提供人情、建议、偶尔反对 |
| 死后继承 | 任意 | -0.10 | 必然触发争产判定 |
| 遗嘱指定 | 花 50 铜，任意年龄可立 | +0.05 | 争产概率减半；可随时改 |

**生前交班**是给玩家的"主动收束"：你可以活着看到孩子接手，用最后几年当顾问——这比等死更有掌控感。

### 20.10 继承结算页（UI 流程）

### 20.11 家族面板

新增第 7 个 tab「家族」（或左栏身份槽点开的抽屉）：

- 三代家谱：祖辈（灰）/ 父辈 / 我 / 子嗣，节点显示年龄、职业、关系、继承顺位。

2. 少东家开局合法性落在 **0.40–0.60**，且 24 个月内至少出现 1 次"合法性危机"议程。
3. 债务、仇敌、人情按表继承，且在结算页与家族面板上可逐项核对。
4. 多子嗣时争产 **100%** 触发（分家/收买/打压三条路都走得通）。
5. 选择"生前交班"时合法性不低于 0.5，且前任以长老身份可交互。
6. 继承后首月必须有一张"家书"说明处境，而不是静默继续。
