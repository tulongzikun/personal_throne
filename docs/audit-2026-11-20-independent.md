# 独立试玩审计（2026-11-20）与修复计划

五个只读子进程分别从经济/叙事/界面/长期模拟/健壮性角度试玩，结论一致：
**可复现、可存档、可校验，但“好玩”与“活着”都不成立。** 综合评分 3.3/10。

原始报告要点保留在此，作为后续修复的验收基线。所有数字均为 2026-11-20 在
`14acd16` 附近的树上测得；修复后需重新测量并更新本文件的“修复后”列。

## 二、最要命的事实（按可验证性排序）

1. **建议事项面板从未渲染**：`PlayerPanel.update()` 的 `clear(host)` 把同挂在
   `playerRail` 上的 `.suggestions` 一起清掉。已修（独立容器 + 回归测试）。
2. **「考察市场」是空转**：只能考察所在地，而当地价格本就精确可见。已修
   （可派伙计打听相邻地区，20 铜 + 1 行动力）。
3. **贩货写死粮食**：11 单位 grain 赚 31、iron 64、luxury 449。已修（按最优
   路线显示与发送）。
4. **`train` 无技能白名单**：`skill:'bogus'` 会写进存档。已修。
5. **死亡不设防**：`alive=false` 后 `invest/recruit/take_loan/buy_asset/
   buy_shares/set_strategy` 仍 `ok:true` 并改钱。
6. **`NaN` 穿透**：`units: NaN` 走完整条贸易，财富与库存变 `NaN`，
   `validateWorld` 放行，存档写成 `null`。
7. **老档 `contracts` 是数组时**：迁移只补字段不换容器——非空读不进，空数组
   则新契约下次存档静默丢失。
8. **解散的组织会复活**：`stats.dissolved=12` 而实体只有 6。
9. **继承不看血缘**：25 次更替仅 1 次（4%）是前任子女；出现 7 岁女王 +
   128 岁摄政、遗产“股份 140%”。
10. **僵尸国**：0 地区 0 人口仍背 9 亿债务、厌战冻结、战争不停；100 年国债
    ×2470。
11. **经济不闭合**：10 年 M2 ×2.7，CPI 只 +5%；单月工资 7,475 只有 1,900 到人。
12. **成长线自锁**：训练上限 7，生涯顶阶要技能 9；公职评分 39 < 门槛 45。

## 三、验收口径（修复后必须重测）

- 躺平 vs 主动：40 年净资产比 **≥ 2.0**（当前 1.21）。
- 组织破产率 100 年：**20–30%**（当前 32–45.5%）。
- 分裂率：**8–15%**（当前达标）。
- `sigma(机构现金) / 期初` 不得单调发散；国家债务/收入比有上限。
- 历史中“事件与里程碑”占比 **≥ 25%**（当前 8.4%）；玩家相关 ≥ 5%。
- 首屏 `.suggestions li` = 3（已加测试）；首屏可见按钮 ≤ 20。
- `tsc` / `eslint` / `prettier` / `vitest` 全绿；100 年单跑 < 4.0 s。

## 四、六阶段修复计划

### 阶段 1：让“做事”成为最优解
- 生涯俸禄与出勤/组织盈利挂钩；非成员可通过劳动（打工/跑腿）获得收入。
- 现金持有成本：通胀侵蚀或月度资产税，避免“囤钱最优”。
- 验收：主动 vs 躺平 ≥ 2×；躺平 40 年不超过 20×。

### 阶段 2：账本闭合
- 工资发到具名角色；建立“家庭钱袋”（人口现金池），消费从池里出。
- 物价对货币量有响应（数量方程或需求侧预算约束）。
- 国债拆成债权人（银行/贵族），还本付息有对手方；公共工程产生实际产出。
- 验收：工资到人比例 ≥ 90%；M2/CPI 相关系数 > 0.5；国家账本三处闭合。

### 阶段 3：失败与边界
- `applyCommand` 入口统一死亡检查；`Number.isFinite` 全量校验；`isAmount`
  用于所有数量；原型键用 `Object.hasOwn`。
- 契约容器迁移修正；存档哈希缺失即拒绝；缺字段统一 `SaveError`。
- 验收：fuzz 5000 条命令 0 未捕获异常、0 负值/NaN；老档可读。

### 阶段 4：继承法与僵尸国
- `chooseRuler` 读血缘与继承法（primogeniture/elective）；摄政有年龄上限。
- 0 地区国走灭亡/被吞并状态机；`dissolved` 不可复活；股份与遗产比例 clamp。
- 验收：100 年更替中子女继位 ≥ 40%；无 0 地区国存活 > 5 年；无“股份 > 100%”。

### 阶段 5：叙事
- 事件正文与结果写进历史（`HistoryRecord.body`）；账本按月折叠，默认视图只显示大事。
- 见闻去重并分级；死亡/继承/战争生成 2–3 句叙事。
- 验收：事件+里程碑占比 ≥ 25%；同一句模版占比 ≤ 40%；玩家相关 ≥ 5%。

### 阶段 6：界面与性能
- 建议事项（已修）复核；对比度 ≥ 4.5:1、字号 ≥ 0.75rem；tab aria、焦点陷阱。
- Tour 第 2 步改为“行动力花在哪”；StartDialog 期间暂停。
- 性能门禁收紧到 4.0 s；`--check` 输出耗时。

## 五、开工前的状态判定（重要）

工作区在审计期间出现一份**并发进行中的拆分重构**（`WorldTypes.ts` +
`src/core/commands/*`，删除 `races/classes/items.json` 与 `SkillCheck.ts`）。
开工前必须先判定：

1. `tsc --noEmit` 是否全绿；若红，看错误是否集中在 `src/core/commands/*`。
2. 相关文件 mtime 是否仍在变化（说明还有人在写）。
3. 处理规则：**若 2 小时内无人再写且错误 ≤ 10 个 → 我接手修完**；
   否则 `git stash push -u -- src/core` 存档并把工作树恢复到 `14acd16` 再开工，
   stash 前把 diff 备份到 `.tmp/refactor-backup/` 并在提交信息里注明。
